# 改进方案

> **判据（小布的要求）**：模块必须有 **taste** —— 不能是「别人的 A 换个名字和细节」。
> 判定标准：**这个模块能不能从一个重新表述里推导出来？**
> 如果只能回答"因为 RAG 一般都会加 X"，那它就是技术组合，不是研究。

---

## 一、标尺：FreeChunker 的故事为什么好

先拆解它自己，才知道什么叫"推导出来的设计"。

1. **重新表述问题**：chunking 不是「找边界」，而是「**检索时选跨度**」
2. **机制从表述里掉出来**：既然检索对象是跨度，就需要**廉价地编码大量跨度**
   → 于是必然有「可学习 chunk 查询向量 + 句子向量当 K/V + 一次前向」
3. **准确率与效率来自同一个设计决定**，不是两个 trick 拼起来

注意第 3 点：论文的效率优势（比语义分块快 30×）**不是加了一个加速模块**，
而是「不做边界检测」这件事的**副产品**。这才是 taste。

**所以本方案的自检问题**：我加的这个东西，是"因为范式是这样的，所以必然如此"，
还是"因为别人都加了"？

---

## 二、体检：FreeChunker 的「检索时自由」其实只做了一半

论文的口号是"把粒度从切块时移到检索时"。但把流水线拆成四步看：

| 环节 | FreeChunker 的做法 | 真的"检索时自由"吗 |
|---|---|---|
| ① 候选**生成** | 预设 (1,2,4)，**全部**物化 | ✗ 粒度菜单是**超参**，不由查询决定 |
| ② 候选**表示** | `h_chk` 是**一个常数向量复制 m 份** | ✗ 所有 chunk 向量是"泛化 chunk"，**与查询无关** |
| ③ 候选**打分** | 原始余弦，跨粒度**直接混排** | ✗ 不同粒度的分数**不可比** |
| ④ 候选**组装** | 取 top-k → 去重拼接 | ✗ 论文自称"deterministic post-processing"，**是启发式** |

结论：**"自由"只发生在第 ④ 步的选择动作上，而这一步用的分数本身没校准、
选择规则还是启发式。** 范式把粒度解放了，却没给"选出来的东西怎么组装"一个交代。

---

## 三、主线：**重叠不是副作用，是这个范式唯一多出来的结构**

### 3.1 重新表述

传统分块切出来的块是**互斥**的 —— 切完就不重叠。
所以在互斥的块上「取 top-k」是合理的：每块都带来新信息。

FreeChunker 的候选**按构造就重叠**（`step_size = g//2`，相邻候选重叠 50%）。
于是在它的候选集上「取 top-k」变成**系统性次优**：

> 分数最高的 k 个候选很可能高度重叠。
> 去重后真正覆盖到的句子，可能只有 3–4 句。
> **你检索了 10 个 span，却只拿到了很少的信息。**

论文把重叠当成"需要一个确定性后处理来收拾的麻烦"。
**我们认为反过来：重叠是这个范式唯一多出来的结构信息，而论文没有用它。**

### 3.2 为什么这个落点是"范式独有"的

FreeChunker 为**每个句子**维护全局索引 `[Begin-t]/[End-t]`。
这意味着 —— **任意候选集合「覆盖了哪些句子」「哪些句子被重复覆盖」都是精确可算的。**

论文只用它做**拼接**。没有用它做**选择**。

这一步很关键：**换成任何固定粒度分块，句子级覆盖根本无从定义**
（块是原子，你不知道块内哪些句子被重复覆盖了）。
所以下面这个方法**只在"句子为原子单位"的范式下才写得出来** ——
它是范式的必然延伸，不是外挂模块。

这也是它不能叫「MMR for RAG」的原因：那不是通用集合选择，
问题是**新范式自己创造出来的**（候选按构造重叠）。

### 3.3 M1 · Coverage-Aware Span Assembly（CASA）★ 主方法

**把「选哪些候选」从启发式提升为有保证的组合优化。**

目标：在 token 预算 B 下选候选集合 S，最大化

```
F(S) = Σ_{i∈S} rel(i)              ← 相关性（余弦分，做粒度校准）
     + λ · |⋃_{i∈S} sentences(i)|  ← 句子级覆盖（范式自带，精确可算）
     − μ · Σ_{t} (cover_count(t) − 1)   ← 重复覆盖惩罚
```

三个性质让这个方法**不是拼凑**：

1. **精确而非近似**：边际增益 `F(S∪{i}) − F(S)` 可以用全局索引**精确算**，
   不需要近似覆盖（对比：一般文档集合选择要用 n-gram 近似）
2. **有理论保证**：`F` 是次模的（覆盖函数是经典次模函数）→ 贪心有 **1−1/e** 保证
3. **零额外模型**：不需要 reranker、不需要 BM25、不需要 LLM 调用。
   它利用的是**范式本来就存下来的索引**

**预期**：Top-5 提升最明显（top-k 小时重叠最严重）。
而且**顺带降低开销**：同样预算下用更少的候选达到更高覆盖 → 检索更少。

**怎么验**：固定 top-k 与 budget，只替换选择规则，对比 Overall + 分域 + 实际覆盖句数。

**风险**：低。纯后处理、可开关、失败可回退。

### 3.4 M2 · Lattice-Consistent Span Embedding

**候选空间不是袋子，是格。**

g=4 的 span 由两个 g=2 组成，g=2 由两个 g=1 组成。
论文把它们当**扁平候选袋**，各尺度**独立打分**。

后果：会出现「一个 4-span 分数很高，但它内部最好的 2-span 分数很低」这种
**跨尺度不一致** —— 而人判断"这段该不该被检索"时，粗看细看应该是一致的。

两个用途，**都不需要外部数据**：

1. **训练信号（要重训）**：加跨尺度一致性正则 ——
   粗粒度的分应与其内部细粒度分的聚合一致。
   这是**从格结构里掉出来的监督信号**，不是通用正则。
2. **检索（免重训）**：粗粒度做**粗筛**，候选集降一个数量级 → 开销与准确率同时改善。

### 3.5 M3 · 负样本从格结构里自动生成（要重训）

现在是**余弦蒸馏**：拟合真值 `e = M(concat(s_i..s_j))`。
目标是「像」，**不是「排得对」**。论文自己报告 ρ≈1（拟合得很好），
但拟合得好不等于检索排序对。

而候选族**天然提供最难负样本**：
把正样本平移一个 `step_size` 得到的 span，**只差一句**。
这类负样本比随机负样本难得多，而且**不需要任何外部数据或 query 标注**。

→ **监督信号从范式里免费掉出来。** 这是 M3 的 taste 所在。

**风险**：要重训（我们上次训练约 13 小时 / 8×3090，可接受）。
放在 M1、M2 之后做。

### 3.6 一句话的论文故事

> FreeChunker 把粒度从「切块时」搬到了「检索时」，代价是候选**按构造重叠**。
> 论文把这个代价交给一个"确定性后处理"收拾。
> 我们指出：**重叠不是需要收拾的麻烦，而是这个范式唯一多出来的结构** ——
> 它让「任意候选集合的句子级覆盖」第一次变得**精确可算**。
> 基于这一点，我们把上下文组装从启发式提升为**有 1−1/e 保证的组合优化**，
> 并进一步发现候选空间具有**格结构**，用它同时改进了训练信号与检索效率。

**三段式**：诊断（重叠被误解）→ 方法（覆盖感知组装）→ 拓展（格结构）。

## 四、明确**不做**的（这些是"换名字的 A"，写不成故事）

列在这里是为了**避免自己以后又绕回去**：

| 候选 | 为什么不做 |
|---|---|
| BM25 混合检索 | 教科书 A+B。换个名字（"hybrid retrieval"）本质没变 |
| Cross-encoder 重排 | 同上，且会摧毁 FreeChunker 的效率叙事 |
| Query expansion / 多查询融合 | 通用 RAG trick，与"句子为原子单位"这个前提毫无关系 |
| 粒度组合网格搜索 | 调参不是贡献 |
| 向量量化 / PQ 压缩 | 纯工程，与范式无关 |
| 对比学习（随机负样本） | 通用做法；**但如果负样本来自格结构（M3），就成立** |

**判断口诀**：如果一个改动**换成固定粒度分块也照样能加**，那它就不是这个故事的一部分。

## 五、仍要先对齐的两件事（不算改进）

- **W1**：`FC_MAX_SENTENCES=4000` 的句子窗口影响面统计。
  N ≤ 4000 已验证与原实现逐位一致；N > 4000 的长文档在窗口边界无法形成 chunk。
  **这关系到基线本身可不可信，必须最先做。**
- **W2**：vLLM 上下文上限 32768（原 40000）的截断率统计。
