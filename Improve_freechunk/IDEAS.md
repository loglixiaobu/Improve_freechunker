# 研究主张

> **定位**：不是"改进 FreeChunker"，而是**把同一个故事讲到底**。

---

## 0. 为什么"提出自己的方法"比"改进 FreeChunker"更好

| | 改进 FreeChunker | 提出自己的方法 |
|---|---|---|
| 赛道 | 在他们的实现细节上比 | 我们自己选这个故事的最强形式 |
| 叙事 | "我们加了 X，涨了 0.8 个点" | "我们把范式推到底，发现它漏了一件事" |
| 审稿人 | 容易被视为 incremental | 更像"指出并解决了一个结构性问题" |

而且有一个很硬的理由：**这是论文自己写下的 future work。**

> "the chunk-pattern mechanism `P_{g,s}[i,j]` could in principle be extended to
> more complex **non-contiguous compositions**."
> —— FreeChunker 论文 Limitations

**回答作者自己提出的开放问题，是很强的 positioning。** 不是抢他们的活，是接着往下做。

## 1. 重新表述：「跨度」这个词还留着一个假设

FreeChunker 的故事：**chunking 不是找边界，是检索时选跨度。**

我们的故事：**"跨度"（span）这个词自带一个假设 —— 证据是连续的。把它去掉。**

这个假设对 single-doc 成立，对 **multi-doc / multi-hop / long-icl** 不成立 ——
那里的证据天然**分散**在多处，任何连续区间都装不下。

### 与已有工作的差异（这两条都要能说清，否则就是"换名字的 A"）

| 方法 | 检索单位 | 强制连续？ | 集合是单位？ |
|---|---|---|---|
| 传统分块 | 固定块 | — | ✗ 块是原子，谈不上集合 |
| Proposition / 句子级检索 | 单个命题/句子 | — | ✗ **各句子彼此独立** |
| FreeChunker | 跨度 | ✅ **强制** | ✅ |
| **本方法** | **证据集** | ✗ 任意 | ✅ |

两条差异都是硬的：
- 相比 **FreeChunker**：去掉了"连续"这个**不必要的**限制
- 相比 **句子级/命题级检索**：保留了"**集合本身是检索单位**" ——
  返回的是**一个共同构成答案的证据集**，而不是 top-k 个彼此独立的句子。
  后者丢掉了"它们要一起读"这件事。

## 2. 机制：为什么这是"去掉限制"而不是"加模块"

这是 taste 的落点。

FreeChunker 的注意力是：

```
Attn = softmax( QKᵀ/√d + P ) · V
```

`P ∈ {0,−∞}^{m×n}` 是 **Chunk Pattern Mask**。
论文里 P 是**固定带状**的：`P_{g,s}[i,j] = 0 iff s ≤ j < s+g`。

**但数学上 P 完全不需要是带状的** —— 带状只是作者为了**枚举方便**做的选择
（枚举所有 (g,s) 就能列出所有候选）。

所以：

> **带状是一个先验（prior），不是一个约束（constraint）。**

我们要做的，是**把 P 从预设对象变成可学习对象**，
让**数据自己决定**证据该有多分散 —— 而连续只是它的一种特例。

### 具体怎么做到"不枚举也能有候选"

难点：非连续组合的枚举是组合爆炸（从 n 句里选若干段）。

解法：**不枚举，而是生成。**
- 保留句子向量 `E` 与掩码注意力 —— **一次前向的效率优势不能丢**
- 候选由 `K` 个**可学习组合模式**（codebook）产生：`模式 × 起始位置`
- `K` 很小（8–16）→ 候选数仍是 `O(K·n)`，与现有同量级
- 用**结构先验**（如 total-variation / group-lasso 型正则）鼓励"段状支持"，
  但**允许**在数据要求时散开

这给了一个**可解释的旋钮**：从"严格连续"到"完全自由"。
于是实验设计天然成立：

- 正则调到最紧 → 应当**复现** FreeChunker（sanity check）
- 逐渐放松 → 观察 multi-doc / long-icl 是否改善

**这本身就是论文里最好看的那张图。**

### 顺带解决的一件事

一旦检索单位是句子集，**"从重叠候选里重建上下文"这个问题自动消失** ——
你选出来的就是句子集本身。
论文那个"deterministic post-processing"从**补丁**变成了**方法的一部分**。

## 3. 三个组件（每个都是"证据集"这个表述的推论，不是拼装）

### C1 · Learned Chunk Patterns ★ 核心

把 P 从固定带状 → 可学习稀疏支持（见上）。
**这是唯一改模型的部分，也是论文的主要贡献。**

### C2 · Coverage-Aware Selection

既然检索单位是**集合**，选择目标就不该是"排序取 top-k"，而应是**覆盖**。

- 论文为每个句子维护全局索引 `[Begin-t]/[End-t]`
  → **任意候选集合的句子级覆盖精确可算**，论文只用它做拼接
- 边际增益可精确计算（不需近似覆盖，对比一般文档集合选择要用 n-gram 近似）
- 目标次模 → 贪心 **1−1/e** 保证
- **零额外模型**（不用 reranker / BM25 / LLM）

⚠️ 注意：**这条单独拿出来是"通用集合选择"，不新鲜**。
它成立是因为 C1 把检索单位变成了集合 —— 它是 C1 的**推论**，不是独立卖点。

### C3 · Set-Level Contrastive Training

现在是余弦蒸馏，目标是"像"，不是"排得对"。
而组合族**天然提供最难负样本**：把证据集里的一个句子换掉/平移，**只差一句**。

→ **监督信号从范式里免费掉出来**，不需要任何外部数据或 query 标注。

## 4. 先做的诊断实验（便宜、可立刻做、且是论文的 motivation）

**不动模型**，用现有 FreeChunker 的输出 + 已切好的数据就能算：

| 诊断 | 怎么算 | 说明什么 |
|---|---|---|
| **D1 · 冗余率** | top-k 覆盖的句子并集 ÷ top-k 的句子总数 | 现在到底浪费了多少预算 |
| **D2 · 选择天花板** | 同预算下「按分数 top-k」vs「贪心最优集合」的准确率差 | **C2 的收益上限** |
| **D3 · 分散度** | 被选中的 span 在文档中的分布（是否总挤在一处） | 连续假设是否真的是瓶颈 |
| **D4 · 粒度菜单消融** | 只改 `granularities`（免重训，用未训过的档位试） | 固定菜单是否限制长上下文域 |

**D2 最有价值**：它给出"C1+C2 最多能涨多少"的**上界估计**。
如果上界只有 +0.3pt，整个方向就不值得做 —— **先花一天把这个问清楚，比闷头实现强。**

---

## 5. 诚实的风险

1. **非连续检索可能没用**：LongBench V2 的 MCQ 也许答案证据本来就集中在一处，
   那"分散"这个 motivation 就是假的。
   → **D3 就是用来证伪这一点的。如果 D3 显示证据本来就集中，这个方向要重做。**
2. **Proposition retrieval / ColBERT 已在附近**：必须把"集合是单位"这条差异讲清楚，
   否则会被归为组合创新。
3. **可学习掩码可能学不到东西**：如果正则太强就退化成 FreeChunker，
   太弱就变成无结构的注意力。需要找到那个旋钮的位置 —— 这本身是实验工作。
4. **算力**：改模型要重训（上次约 13h / 8×3090，可接受）。
   C1 之前的部分都免重训。

## 6. 排期

```
D1–D4 诊断（CPU/现有产物，不碰 GPU）
   │
   ├─ D3 显示"证据确实分散" ──► C1 实现 + 重训 ──► C2 ──► C3
   │
   └─ D3 显示"证据本就集中" ──► 回头重选故事（别硬做）
```

**关键：D3 是 go / no-go 闸门。** 先做诊断再动模型。
